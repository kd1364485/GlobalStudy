The problem with one request at a time

  • A small model finishes its math in microseconds.
  • Every call still pays a fixed cost.
  • Data is copied to the GPU and kernels are launched.
  • With one input per call, that fixed cost dominates.
  • Most of the GPU sits idle while requests wait in line.

The trade-off

  • Requests wait for a batch.
  • A timeout limits the wait.
  • Light load means small batches.
  • Small batches mean less gain.
# worker loop (pseudocode)
while running:
    batch = queue.pop_many(
        max_items=8,
        timeout_ms=2)
    inputs = stack(batch)
    outputs = model.run(inputs)
    reply_each(batch, outputs)
